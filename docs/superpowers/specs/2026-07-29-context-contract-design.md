# ios-genesis v0.7.0 — Context Contract

## Problem

ios-genesis burns tokens because subagents receive the whole project instead of the slice they need. Two mechanisms drive it:

1. **The dispatch contract re-ships full bodies.** `SKILL.md` mandates that *every dispatch include all context the subagent needs*, so `architecture_summary` and `design_summary` are embedded **whole** into the developer, then the verifier, then the test engineer, then the reviewer — O(phases × full-doc). For `feature_addition` the scope summary is stored as **text in `state.json`** and re-shipped to every phase.
2. **Cold subagents explore.** A worker with no map lists directories and reads whole files (the classic failure: reading a 900-line view to change one modifier), and reads expensive files that are never worth their cost (`project.pbxproj` alone can be 20k+ tokens).

The v0.6.0 quick-fix lane cut this for *small* changes by removing phases. This feature cuts it for the **full pipeline** — the multi-task `new_app` / large `feature_addition` runs where a 6-task graph re-ships the design doc six-plus times.

The governing principle (Giorgia's framing): **never let an agent explore — make exploration unnecessary by giving it a cheap map and a precise way to jump.** The target invariant: the orchestrator runs a whole session carrying *handles*, never file bodies; workers open with exactly their slice loaded.

## Decisions made during brainstorming

- **Scope: levers 1–5 of the progressive-disclosure blueprint** (repo map, search-before-read, deny rules, Haiku two-phase retrieval, refs-not-bodies). Lever 6 (Skills for iOS knowledge) and lever 7's module-split reading are deferred (§7).
- **Repo map owned by the orchestrator, regenerated per phase.** `.ios-orchestrator/symbols.txt`, regenerated at each phase start and after each wave-end integration build (rides the existing build-serial rhythm). Gitignored. No user setup, no committed artifact, always fresh against the last build.
- **Context Scout is a new `model: haiku` agent, gated to reads-existing-code dispatches.** It runs before feature_addition workers, `test_engineer`, `code_review`, `integration`, and `address_visual`/`address_review` fixes — never before greenfield foundation/screen writes (nothing to scope).
- **Refs-not-bodies dispatch contract.** Dispatches carry handles (paths + section anchors) and minimal state, not doc/file bodies. The feature_addition scope summary moves from `state.json` text to a gitignored `.ios-orchestrator/scope.md` so it is refable without shipping a stale artifact in the repo. `architecture.md`/`design.md` gain stable section anchors.
- **Search-before-read is a hard rule in every worker prompt.** `grep -n` then Read with `offset`/`limit`; never read a >~300-line file whole. The Scout's ranges are a floor, not a ceiling.
- **Deny expensive reads** (`project.pbxproj`, `Package.resolved`, `*.xcodeproj/**`, `Pods/`, `DerivedData/`, `__Snapshots__/`, generated clients, non-base `*.strings`) — delivery mechanism (plugin-shipped vs documented `settings.json`) confirmed at implementation; the design carries both paths.
- **Ships as v0.7.0.** Module-split is a separate v0.8.0 because it changes the build model, not just context.

## 1. Repo map — `.ios-orchestrator/symbols.txt`

A compact symbol index the orchestrator generates and workers/Scout read instead of listing directories.

- **Generation:** `grep -rn -E "^\s*(public |internal |private |final |open )*(class|struct|enum|protocol|actor|extension) " --include="*.swift" <sources>` piped to strip trailing `{...` — one line per declared type as `path:line: <decl>`. A few thousand tokens for a large app.
- **When:** regenerated by the orchestrator at each phase start (before dispatching that phase's first wave) and after each wave-end integration build (so it reflects code the wave just wrote). Written to `.ios-orchestrator/symbols.txt`.
- **Mode dependence:** meaningful only once code exists. `feature_addition` has it from the first phase (existing codebase). `new_app` has nothing to index until `foundation` builds; the earliest phases scaffold from `architecture.md` (which *is* the map for greenfield writes), and `symbols.txt` becomes populated from the foundation wave onward — used by `integration`, `test_engineer`, `visual_verification`, `code_review`.
- **Gitignored:** lives under `.ios-orchestrator/`, already ignored and scope-check-exempt (see `state-schema.md`).

## 2. Context Scout — `agents/ios-context-scout.md` (`model: haiku`)

A cheap scoping pass that replaces the worker's exploration phase.

- **Input (dispatch prompt):** the task's scope text (or `scope.md#section` ref), the worker's `owned_files`, and the contents of `symbols.txt`. No Swift bodies.
- **Output (report):** JSON — `{ "files": [ { "path": "...", "ranges": [[start,end], ...], "reason": "..." } ] }` — the exact files and line ranges the worker should load to do its task, chosen from `symbols.txt` + a minimal number of its own targeted reads. It may `grep`/`Read` narrowly to resolve ranges but returns **handles, never contents**.
- **Tools:** `Read, Grep, Glob` (read-only). No Write.
- **Orchestration:** for a reads-existing-code dispatch, the orchestrator dispatches the Scout first, then injects its `files`/`ranges` into the worker's dispatch prompt as an explicit *"Load exactly these ranges; do not explore beyond them without cause"* block. The worker still performs its own `Read` calls (cold), but guided — no discovery round-trips at the expensive tier.
- **Gating:** runs for feature_addition developer/test/review workers, `integration`, `test_engineer` (reads `source_files`), `code_review`, and `address_visual`/`address_review` re-dispatches. **Skipped** for `new_app` greenfield `foundation`/`screen` writes (nothing to scope). A future second gate (only when candidate files exceed ~300 lines) is noted but not built now.
- **Cost note:** the Scout adds one Haiku dispatch before each scoped worker. On a change touching a single small file the Scout's overhead can exceed the saving; the reads-existing-code gate keeps it off the cases where it wouldn't pay.

## 3. Refs-not-bodies dispatch contract

The core contract change.

- **`SKILL.md` note (currently line ~49):** *"every dispatch must include all context the subagent needs"* → *"every dispatch includes the handles (file paths + section anchors) and minimal state the subagent needs; the subagent reads its own slice. Never embed file or doc bodies in a dispatch or in the orchestrator's own reasoning."*
- **Architecture/design refs:** `architecture_summary`/`design_summary` dispatch inputs become refs — `docs/architecture.md#<Module>` / `docs/design.md#<Screen>` — not bodies. Requires stable section anchors:
  - `ios-architect.md` writes `## <ModuleName>` and per-screen subsections with predictable headers.
  - `ios-ui-designer.md` already writes per-screen sections under canonical screen names (screens register under their `docs/design.md` names for the router); make those anchors the addressing contract.
- **feature_addition scope artifact:** the Architect writes its scope summary to gitignored `.ios-orchestrator/scope.md` (with `## <section>` anchors) instead of returning it as `state.json` text. Dispatches pass `scope.md#<section>` refs. This preserves the "no stale artifact in the shipped repo" property (`.ios-orchestrator/` is ephemeral and gitignored) while making the summary refable. `state.json`'s `architecture_summary` becomes a pointer to `scope.md` rather than the body.
- **Orchestrator invariant:** the orchestrator holds zero file/doc bodies in its own context — it passes handles and reads only the small control fields it needs (task graph, statuses, refs). Artifact *content* surfacing at checkpoints (required by `checkpoints.md`) is done by reading the specific section at checkpoint time, not by holding the whole body throughout.

## 4. Search-before-read rule

Added to every worker `agents/*.md`:

> Before reading a file, `grep -n` for the symbol/string you need, then `Read` with `offset`/`limit` around the hits. Never read a file over ~300 lines in full. When your dispatch includes a "Load exactly these ranges" block (from the Context Scout), start there.

This makes narrow reads the default even for the un-scouted greenfield writers (which still occasionally read foundation outputs).

## 5. Deny expensive reads

A deny list for files never worth their token cost: `**/*.pbxproj`, `**/Package.resolved`, `**/*.xcodeproj/**`, `**/Pods/**`, `**/DerivedData/**`, `**/__Snapshots__/**`, generated API clients, and non-base `*.strings` (`*/??.lproj/*.strings` except `Base.lproj`/`en.lproj`).

- **Delivery (confirmed at implementation):** if a plugin can ship permission/deny rules (via a bundled `.claude/settings.json` or equivalent), ship them so the protection is automatic on install. If not, document a one-time `settings.json` snippet in the README install section and have the orchestrator instruct workers (in their prompts) never to read these paths as a belt-and-suspenders fallback.

## 6. New reference doc — `references/context-contract.md`

One canonical doc describing the whole scheme (map generation, Scout protocol, refs-not-bodies contract, search-before-read, deny list) so the orchestration/agent docs can point at it instead of restating it. Loaded as needed, like the other reference docs.

## 8. Validation

Token savings cannot be unit-tested. Validation is a real `feature_addition` run (Cadenza's backlog is the natural target) that confirms:

- Workers' dispatch prompts carry refs, not bodies (inspect the dispatches).
- Workers load only the Scout's ranges and do not list directories or read whole large files.
- No worker reads a denied path.
- The orchestrator's own context never contains Swift/doc bodies across the run.
- End-to-end output is unchanged from a v0.6.0 run of the same change (the contract is a plumbing change, not a behavior change).

## 9. Out of scope (deferred)

- **Module-split / SPM local packages (blueprint lever 5).** Scoping subagents by package collides with ios-genesis's load-bearing "single shared Xcode target — compilation is an integration act" principle (`orchestration-flow.md`). It changes the build and integration model, not just context. Its own **v0.8.0**.
- **iOS knowledge as Skills (blueprint lever 6).** Subagents don't invoke the Skill tool the way the orchestrator does; the Swift/SwiftUI knowledge lives inline in the agent prompts today. Needs a mechanism spike before it can move.
- **Per-role model routing beyond the Scout.** The Scout introduces a second model tier (Haiku); a full per-role routing pass (stronger for architecture/review, faster for mechanical fixes) remains the roadmap item it already was.
- **>300-line second gate on the Scout.** Noted as a future refinement; the reads-existing-code gate is the v0.7.0 rule.
